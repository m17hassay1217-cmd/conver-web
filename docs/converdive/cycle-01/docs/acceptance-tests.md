# Acceptance checks

## Navigation / structure
- Ten numbered sections exist in the correct order, with Section 01 hero and Section 10 contact (splash resides inside the Section 01 entry region).
- Sticky header anchors jump to target; no obscured headings; keyboard operable.
- Section background changes are restrained; reduced motion and touch behavior do not hide information.

## Section 04 technical proof
- Four causes exist with exactly two intermediate mediators each; visible problem and proposed upstream controllable condition shown simultaneously.
- Active card large and readable; inactive neighbors visually recede; switching to all four works using scroll, buttons and keyboard.
- The first reveal concept exposes a stylized 3D thickness; it cannot imply a 3D asset when only CSS is rendered.
- No unsupported claim of proven root causes or guaranteed fixes.

## Section 05 technical proof
- Four methodology states in order and one separate differentiation synthesis.
- Text transitions are related to instrument state but remain readable.
- No requirement to reload previous methodology visuals in the final differentiation reveal.
- Exit resumes ordinary vertical scrolling.

## Section 06–08 skeleton
- Four clickable scenarios; state change is understandable without relying solely on color.
- Section 07 has **three** ripple states, not six.
- Section 08 is one continuous diagram that accumulates control layers, final bright stage at fourth milestone.

## Calculator/contact
- Formula is auditable and labels distinguish gross revenue from profit and opportunity from promised results.
- Number fields reject negative values and rates outside 0–100%.
- Form cannot silently pretend to send submissions: show demo status until backend is connected.
- No credentials embedded in source or client JavaScript.

## Before production deploy
- Run build/typecheck/lint/test (once dependencies are available).
- Check 375px, 768px and 1440px widths; Chromium, Firefox, Safari where available.
- Lighthouse/DevTools: layout shift, rendering load, accessibility, no horizontal overflow.
- Form delivery confirmation via real test inbox, call/booking link validation, privacy notice and consent workflow as required.
- Disable debug content/mock metrics, verify text truthfulness and make a rollback tag.
