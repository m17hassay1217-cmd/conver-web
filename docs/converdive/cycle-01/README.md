# Converdive — First Development Cycle

**Status:** A browser-tested, dependency-free interaction prototype and an Antigravity-ready specification pack. **Not a launched production website.**

## What exists
- A complete ten-section navigable *structural* webpage (splash/hero through contact) in `prototype/`.
- Interactive scroll-scrubbed **Section 04 causal cross-section coverflow** and **Section 05 adaptive instrument / methodology**. These are technical proofs-of-concept using browser-native CSS/JS/SVG; they are not yet Three.js production scenes.
- Basic interactions for Sections 02, 03, 06, 07, 08 and a calculator in Section 09 as structural placeholders; final choreography remains subject to section-specific implementation and review.
- Source-of-truth specs, design tokens, references, motion states, acceptance criteria, custom skills and Antigravity bootstrapping prompt.
- No external API keys or credentials are stored or requested. Contact form is intentionally **demo-only** until a verified backend is connected.

## Preview now (no install)
Run `python3 -m http.server 4173 --directory prototype` from any terminal with Python 3, then open `http://localhost:4173`. You can also open `prototype/index.html` directly, though a local server is preferred for repeatable testing.

## Continue inside Google Antigravity
1. Open this entire `converdive_cycle1` folder as a project (not just the `prototype` folder).
2. Read `AGENTS.md`, `docs/website-master-spec.md`, `docs/design.md`, `docs/acceptance-tests.md`, `docs/antigravity-handoff.md` and the section/motion specs. Read source workflow summaries only for process inspiration, not website factual claims.
3. Paste `docs/antigravity-handoff.md` as the first task and enter planning mode. The next production step is to **port** the prototype into a Next.js/React/TypeScript application, preserving tested behaviors while adding GSAP and Three.js where justified.
4. Preserve all prototypes as reference snapshots. Request permission before overwriting, deploying, connecting accounts, or using paid image/video services.

## Constraints / fidelity
- Section 04: 4 **hypothetical** causal mechanisms, with 2 mediators between visible problem and controllable condition. These are not field-validated root causes.
- Section 05: 4 methodological stages plus **one synthesis**, not a fifth methodology.
- Section 06: 4 guided workflow scenarios, then a unified *illustrative* enquiry-to-booked-work representation.
- Section 07: exactly 3 owner-outcome ripples, not 6.
- Section 08: the four implementation phases are **lifecycle/control layers**, not four separate steps in the cleaning client's sales funnel.
- Section 09: transparent calculator assumptions; gross contract value is not profit or guaranteed return.
- Section 10: voice and text contact, with no invented phone/email credentials.

## Missing prerequisites
A production deployment still needs: domain/hosting, verified contact addresses and phone scheduling provider, secrets managed outside the repo, production data/privacy notice, actual company proof where available, licensed visual media, and npm dependency installation in Antigravity's internet-enabled environment.
